# 스티커 화풍 설계서

2026-11-06 사용자 결정: 지금 스티커는 품질이 매우 낮다. 화풍 설계서를 먼저 쓰고, 팩당 30종으로 정해 하나씩 완전히 새로 그린다. 그림 도구에 따른 재질과 화풍으로 팩마다 개성을 낸다. «코드로 그린 그림의 한계»는 인정하지 않는다.

## 1. 참고 자료와 본 범위

- 네이버 캘린더 스티커 화면 20장(사용자 제공, 2026-11-06). 20장을 한 장씩 봤다. 거기서 얻은 것은 **원리**뿐이고, 구도·소품 배치·캐릭터는 가져오지 않는다.
  - 화풍을 갈래로 나누고, 같은 주제(생활·음식·여가·학업·운동·기념일)를 두 화풍으로 한 번 더 그려 선택지를 준다.
  - 펜 일러스트 갈래: 윤곽선 색 하나로 통일, 부드러운 면 색, 하이라이트와 그림자, 거의 모든 그림에 보조 요소(반짝이·하트·김·땀방울)를 붙이고 대상을 **상황째** 그린다.
  - 플랫 갈래: 윤곽선 없이 면 색과 그림자 면만 쓰고, 사람이 들어간 장면이 많다.
  - 캐릭터 갈래: 표정과 머리 위 장식으로 감정을 말한다.
- 깃허브 스킬: `kv0906/cc-skills`의 `svg-art`, `narumiruna/agent-skills`의 `create-svg-illustrations` 본문을 읽었다. 둘 다 기하 패턴·도식용이라 일러스트 품질에는 쓰지 않는다. «렌더해서 직접 보지 않았으면 봤다고 하지 않는다»만 검수 규칙(6절)에 넣었다.

## 2. 크기 조건 (코드에서 확인)

- 그림 판: `viewBox="0 0 48 48"`, 바깥 여백 3 이상.
- 화면 표시 크기: 달력·기록 칸 24~26px, 상점 미리 보기 48px.
- 그래서 **48px에서 디테일이 보이고, 26px에서는 실루엣만으로 무엇인지 알아봐야 한다.** 디테일은 실루엣을 해치지 않는 안쪽에만 둔다.

## 3. 공통 규칙 (모든 팩)

1. **실루엣이 먼저다.** 대상마다 가장 알아보기 쉬운 각도(컵은 옆, 접시는 비스듬히 위, 사람은 동작이 보이는 옆·3/4)를 고른다. 사각형·원을 이어 붙인 실루엣은 불합격이다.
2. **상황을 그린다.** 물건만 두지 않고 그 일정의 순간을 넣는다. 예: 병원은 건물 대신 청진기와 체온계, 빨래는 세탁기와 비누 거품, 공부는 펼친 책과 연필과 지우개 가루.
3. **빛은 왼쪽 위에서 온다.** 하이라이트는 왼쪽 위, 그림자 면은 오른쪽 아래에 둔다.
4. **보조 요소는 1~2개만.** 반짝이·하트·김·땀방울·움직임 선은 그림의 뜻을 돕는 것만 넣는다(마구 뿌리지 않는다).
5. **팔레트 밖의 색을 쓰지 않는다.** 팩마다 8색(+피부색)만 쓴다.
6. **글자는 쓰지 않는다.** ₩ 같은 기호도 꼭 필요할 때만 쓴다(레터링 팩은 예외).
7. **금지:** 기존 그림의 색·선만 바꿔 새 팩이라 하기, 다른 서비스 그림의 구도·캐릭터 따라 하기.

## 4. 팩 구성 (팩당 30종)

### 4.1 일정 30종 (일정 팩들이 함께 쓰는 주제 목록)

팩 하나만 사도 일상 일정 대부분을 표현할 수 있게 고른 30개다. 각 팩은 이 30개를 **자기 재질로 처음부터 다시 그린다**(색만 바꾸기 금지).

| 묶음 | 주제 |
|---|---|
| 건강 | 병원, 치과, 약 먹기, 헬스, 러닝, 요가, 수영 |
| 꾸밈 | 피부관리, 네일, 미용실 |
| 만남·식사 | 식사 약속, 카페, 술자리, 생일, 데이트 |
| 일·공부 | 회의, 출장, 공부·시험, 수업 |
| 집안일 | 청소, 빨래, 장보기, 택배 |
| 돈·행정 | 은행·공과금 |
| 여가 | 여행, 영화·공연, 독서, 반려동물 |
| 기념 | 기념일·결혼식, 휴식·잠 |

## 6. 부품 라이브러리 (`tools/stickers/`)

여러 그림에 반복되는 조각을 함수로 만들어 품질을 일정하게 한다(따로 그린 그림 파일 묶음이 아니라 코드의 함수다).

- `parts.js`: 팩 화풍(선 색·굵기·팔레트·질감)을 받아 부품을 그린다. 얼굴(표정 10종), 손, 김, 반짝이, 하트, 땀방울, 움직임 선, 바닥 그림자, 하이라이트, 손떨림 선(점 목록 → 흔들린 곡선), 빗금·종이 결·번짐 필터.
- `packs/<팩>.js`: 그 팩의 30종. 그림 하나는 함수 하나다.
- `build.js`: 팩을 `index.html`의 그림 묶음(`svSprite`)에 넣고, 검수용 그림판(`tools/stickers/out/<팩>.html`)을 만든다.

## 7. 검수 관문 (그림 하나마다, 통과해야 다음으로)

1. **크게 보기**: 192px로 렌더해 브라우저에서 본다. 소스만 읽고 «봤다»고 하지 않는다.
2. **작게 보기**: 26px에서 무엇인지 알아보는가.
3. **팩 안 일관성**: 30종을 한 화면 격자로 놓고 선 굵기·색·빛 방향이 맞는가.
4. **베끼지 않았나**: 참고 화면과 나란히 놓고, 구도와 소품 배치가 같으면 다시 그린다.
5. **합격 기록**: 팩을 마치면 이 문서에 «완성 팩» 표로 남긴다(팩, 날짜, 커밋).
