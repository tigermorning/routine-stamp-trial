# 루틴 도장

## 이 앱을 만드는 취지 (설계 원칙)

목표는 **루틴 만들기**다. 처음에는 계획표 없이 오늘 도장 하나부터 시작하게 하는 것은 그 목표에 이르는 수단이다. 루틴이 자리 잡으면 계획 기능이 단계적으로 붙을 수 있다(어떤 기능을 언제 열지는 아직 정하지 않음).

1. 처음 화면에서 고를 것을 늘리지 않는다.
2. 처음에는 계획표·시간표 없이, 오늘 도장 하나부터 시작한다.
3. 줄어드는 숫자와 끊김 경고를 보여 주지 않는다. 놓쳐도 쌓인 것은 그대로다.
4. 새 기능은 뒤에서 열린다. 처음에는 보이지 않거나, 고르지 않아도 저절로 적용된다.
5. 근거를 확인하지 못한 것은 가설로 적고, 써 본 사람의 반응으로 확인한다.

자세한 이유와 근거 수준은 `PRD.md`에 있음

- 칸 세 개에 도장만 찍는 아주 단순한 루틴표 시안
- 처음에는 계획표를 짜지 않고 일단 시작하는 것이 목적
- 기능과 그림은 앞으로 바뀔 수 있음

## 쓰는 법

- 오늘 칸을 누르면 진한 도장(다 했어요), 한 번 더 누르면 연한 도장(조금만 했어요), 또 누르면 비움
- 연한 도장도 그날은 한 걸로 침
- 도장 찍은 날이 3일, 28일, 60일이 되면 칸이 하나씩 열림 (최대 6칸). 일정의 근거와 한계는 `PRD.md`의 "칸 열림 일정과 근거 수준"에 있음
- 처음 여는 사람에게는 첫 방문 선물로 도장 1일이 미리 쌓여 있음. "열림 목표" 카드의 "도장 1일째예요" 옆에 "(🎁 첫 방문 선물 1일 포함)"으로 표시함 (처음 3일 동안)
- 칸이 열리는 날에 화면 색이 자동으로 바뀜 (3일 복숭아, 28일 라벤더, 60일 햇살). 색을 바꾸고 싶으면 ⚙ 설정의 "색 테마"에서 열린 색 중에서 고름(아직 안 열린 색은 "N일째에 열려요"로 보임). 열림 목표 아래에는 다음에 열리는 색이 "다음 색: 복숭아 · 3일째에 열려요"로 한 줄 나옴. 도장 일수는 처음 쓰는 사람의 첫 도장 선물 1일을 포함해서 셈
- "내 루틴" 카드에 칸마다 아이콘, 이름, 그 칸을 찍은 누적 일수("12일째")를 보여 줌. 연속이 아니라 누적이고 줄어드는 숫자는 없으며 "자리 잡았다" 같은 판정은 하지 않음. 그 아래에 별도 "열림 목표" 카드를 두어 칸·색이 열리는 목표(3일·28일·60일), 남은 일수, 다음 색을 한곳에 모아 보여 줌
- ⚙ 설정의 "의견 보내기"에서 글을 복사해 보내 주면 됨
- ⚙ 설정에 "도우미 말투"(이름·말투·이모지)와 "내 OpenAI 키(선택)"가 있음. 키는 이 브라우저 탭의 `sessionStorage`에만 두고(탭을 닫으면 지워짐) 요청마다 `X-User-LLM-Key` 헤더로 보내며, 서버는 저장·기록하지 않고 화면에는 끝 네 자리만 보임. 서버를 `BYOK_MODE=required`로 띄우면 키가 없을 때 운영자 키를 쓰지 않고 안내만 함(기본 `optional`은 키가 없으면 운영자 키)
- 처음 열면 맨 위에 소개 카드(왜 단순한지, 써 보고 의견을 달라는 부탁)와 사용법 카드("알겠어요" 카드)가 나옴. 둘 중 하나라도 닫으면 왼쪽 위에 "안내" 버튼이 나타나, 누르면 두 카드를 다시 볼 수 있음 (두 카드가 모두 열려 있을 때는 이 버튼을 숨김)

## 언어

- 한국어, English, 简体中文, 繁體中文, 廣東話, Bahasa Indonesia, Tiếng Việt, Español, Suomi, Svenska
- 화면 오른쪽 위 ⚙ 설정에서 언어를 고를 수 있고, 고른 언어는 기억함. 설정에는 색 테마, 의견 보내기, 개인정보 안내, 내 기록 지우기(두 번 눌러야 지워짐)도 모여 있음
- 처음에는 브라우저 언어를 따라감

## 저장

- 기록은 쓰는 기기의 브라우저에만 저장됨
- 계정이나 로그인 없음
- 브라우저 사이트 데이터를 지우면 기록도 지워짐
- 기록을 코드로 옮기는 기능은 없앴음(2026-10-21: 코딩을 모르는 사람이 많고 주로 휴대폰으로 써서 어렵다는 판단). 그래서 폰을 바꾸거나 브라우저 데이터를 지우면 기록이 사라짐
- 칸을 빼도 이미 찍은 도장은 남아서, 도장 수와 열린 칸이 줄지 않음
- 화면을 열어 둔 채 날짜가 바뀌어도, 다시 보면 오늘 칸이 새 날짜로 바뀜

## 구성

- `index.html` 한 파일. 도장 찍기는 서버 없이 동작한다.
- `server/` 선택 기능 **대화형 도우미**(루틴 코치 친구) 서버. FastAPI, 무상태, `POST /api/chat` 하나(NDJSON 스트리밍). 오른쪽 아래에 떠 있는 💬 버튼을 누르면 채팅창이 떠오르며(폰에서는 아래에서 올라오는 시트, 도장 화면은 그대로 보임), 루틴 만들기가 어렵다는 고민을 들어 주고(듣기), 방법은 근거 카드(`server/cards.json`, 10장, 출처·확인 수준·한계 표기, 사용자 검수 전)에서만 말하며(조언), 오늘의 한 걸음을 퀘스트 카드로 주며(퀘스트, "받기"를 누르면 오늘 화면에 "오늘의 한 걸음" 한 줄로 보였다가 날짜가 지나면 말없이 사라짐), 이 앱에 대한 질문은 서버의 앱 안내로 답한다(앱). 맞는 카드가 없으면 "근거를 못 찾았어요"라고 알리고 듣기로 돌아간다.
  - 대화는 브라우저 `localStorage`에 저장하고, 요청마다 최근 10턴을 보낸다(할 일 목록은 없앴고 `todos`는 항상 빈 배열, 칸 이름·도장 일수·오늘 칸 상태(안 찍음/진하게/연하게, `context.today`)는 도우미가 앱의 일부이므로 허락 절차 없이 늘 `context`로 함께 보내고(2026-10-21 사용자 결정, 개인정보 안내에는 따로 적지 않음. 오늘 상태는 도우미가 "아침 먹기는 아직이네요"처럼 구체적으로 짚으려고 보냄), 어제까지의 도장 날짜별 기록·사진은 보내지 않음). 서버는 대화를 저장하거나 로그에 남기지 않는다. 위기 표현(자해 등)은 화면에서 먼저 걸러 서버로 보내지 않고 안전 안내를 보여 주며 서버도 한 번 더 거른다. 서버가 없거나 실패해도 도장 찍기는 그대로 동작한다.
  - 로컬 실행(키 없이 가짜 응답): `cd server && pip install -r requirements.txt && python -m uvicorn main:app --port 8893` → http://localhost:8893 (화면과 API가 같은 주소). 진짜 LLM은 환경변수 `LLM_PROVIDER`(openai/gemini/claude)·`LLM_API_KEY`·`LLM_MODEL`로 켠다(키는 파일에 적지 않는다).
  - 도장 그림: `POST /api/stamp` `{"name": 루틴 이름(≤20자)}` → `{"svg": "<svg …>"}`(정리된 SVG 한 개, viewBox 0 0 64 64, 16000자 이하). 허용 태그 밖·`on*`·href·바깥 `url()`은 서버에서 지우고, 이름이 위기 표현이면 그리지 않는다(422). 한도는 대화와 따로 IP당 분당 5회·전체 분당 30회. 오류 400 empty / 422 refused / 429 busy / 502 failed. 키 없는 가짜 LLM은 고정 모양 SVG를 준다. 이름·그림은 저장·로그하지 않는다.
  - 도우미 캐릭터: `POST /api/chat` 본문의 선택 필드 `character: {"name": ≤20자, "speech": "casual"|"polite", "emoji": "none"|"some"|"often"}`(브라우저에 저장해 요청마다 보냄, 서버는 저장 안 함). 필드가 없거나 객체가 아니면 지금까지와 글자까지 같은 기본 동작이고, 허용 목록 밖 값은 기본값(polite·some)으로 정리한다. 설정이 바꾸는 것은 말투 줄과 이름 칸뿐이며 안전·범위·근거 카드·위기 규칙은 설정보다 앞에 있어 그대로다(위기·범위 밖·"근거를 못 찾았어요" 안내 문구는 말투와 무관). 평가: `run_eval.py --character '{…}'`.
  - BYOK(사용자 키): `POST /api/chat`·`/api/stamp`는 요청 헤더 `X-User-LLM-Key`(길이 ≤200, 공백 없는 출력 가능한 ASCII)로 받은 사용자 키를 그 요청 동안만 쓰고(요청마다 새 LLM 객체, 캐시 없음) 저장·로그·응답·오류 메시지에 남기지 않는다. 환경변수 `BYOK_MODE`: `optional`(기본, 헤더가 있으면 그 키로 없으면 운영자 키) / `required`(헤더가 없으면 운영자 키를 절대 쓰지 않고 안내만). 오류: 대화는 NDJSON `{"type":"error","key":"keyMissing"|"keyInvalid"|"keyLimit"}` 한 줄 뒤 종료(HTTP 200), 도장 그림은 401 keyMissing·keyInvalid / 429 keyLimit. 제공사 오류 문구는 전달하지 않고 인증 실패→keyInvalid, 한도·결제(429·402·insufficient_quota)→keyLimit으로만 나눈다. 속도 제한은 사용자 키여도 그대로. 사용자 키는 모양으로 제공사를 고른다: `sk-ant-`로 시작하면 Claude, `AIza`로 시작하면 Gemini(OpenAI 호환 주소), 그 밖(`sk-`, `sk-proj-` 등)은 OpenAI, 모델은 각 제공사 기본값(`llm.PROVIDERS`). 고른 제공사는 로그·응답에 남기지 않고, 운영자 키 경로(헤더 없음)는 `LLM_PROVIDER` 그대로다. 오류 분류는 OpenAI·Anthropic·Gemini 모양을 모두 본다(Gemini 호환 주소는 잘못된 키에 401이 아니라 400 + `API_KEY_INVALID`를 주는 경우가 있음, 커뮤니티 보고).
  - 대화 품질(2026-10-21 사용자 실사용 불만 반영): 말하는 내용의 출처를 셋으로 나눈다 — 루틴 방법·효과는 근거 카드만, 이 앱에 대한 사실은 서버가 가진 앱 안내(`policy.APP_GUIDE`)만, 그 밖의 일반 정보는 "널리 알려진 일반 정보이고 출처는 확인하지 못했어요"라고 밝히고 숫자·연구 인용 없이. 모드에 `app`·`general`을 더했고(done 이벤트에 `basis`: cards/app/general/none), 듣기 모드는 질문만 되풀이하지 않게 직전 답이 질문이었으면 이번엔 요약·선택지·다음 한 걸음으로 끝내게 한다. 말투는 설정이 바뀐 직후 옛 말투 도우미 답을 생략하고 마지막 사용자 말 뒤에 말투 한 줄을 붙여 지킨다. 측정 도구: `python evals/probe.py --env <.env 경로> --tone --convo`.
  - '내 할 일' 목록 제거(2026-10-21 사용자 결정): 이 앱은 일정관리 앱이 아니라 루틴 시작을 돕는 앱이라 화면에서 할 일 목록을 없앴다. 서버는 `todos`를 이전 버전 호환으로 계속 받지만(오면 맥락으로만 씀) `organize`(정리) 모드는 없앴고 모델이 골라도 `listen`으로 처리한다. 한 번만 하는 일(병원·약속)이나 일정을 말하면 `app` 모드가 "지금은 적어 두지 않아요, 이 앱은 루틴 시작이 목적이에요"라고 부드럽게 말하고 "오늘 해 볼 한 걸음 하나만 정해 볼까요?"나 반복할 일이면 "칸으로 만들어 매일 찍어 볼까요?"로 잇는다(앱 안내에 '일정관리 앱이 아니라 루틴 시작을 돕는 앱' 추가, 언제 기능이 붙는다는 날짜·약속은 말하지 않음).
  - 시험: `cd server && python -m pytest tests`(143개, 가짜 LLM). 평가 세트: `server/evals/`(사례 15건 `cases.json`, 판정 `judge.py`, 실행기 `run_eval.py`). `python evals/run_eval.py --fake --all`은 비용 없이 흐름만 확인하고, `--real --env <.env 경로>`는 진짜 LLM으로 핵심 6건(호출 약 12번)을 돌린다(.env 값은 그 프로세스 안에서만 쓰고 출력하지 않는다). 말투·한계 문장 검사는 휴리스틱이라 사람이 답을 읽어야 한다. 진짜 LLM 호출은 아직 시험하지 않았다. 카드 밖 주장을 프롬프트만으로 완전히 막을 수는 없고 평가 세트도 아직 없다.
  - 코드 안 한도: 입력 길이·응답 토큰·타임아웃, IP당 분당 20회·전체 분당 120회(서버 인스턴스 안에서만 셈). 배포와 클라우드 한도(최대 인스턴스·LLM 사용 한도)는 아직 안 했다. 공개 주소 + 실제 키이므로 한도를 건 뒤에만 주소를 공유한다.
