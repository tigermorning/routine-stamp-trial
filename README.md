# 루틴 도장

## 이 앱을 만드는 취지 (설계 원칙)

목표는 **루틴 만들기**다. 처음에는 계획표 없이 오늘 도장 하나부터 시작하게 하는 것은 그 목표에 이르는 수단이다. 루틴이 자리 잡으면 계획 기능이 단계적으로 붙을 수 있다(첫 계획 기능은 누적 60일에 열리는 날짜별 할 일·일정 메모로 정함, 그 밖은 아직 정하지 않음).

1. 처음 화면에서 고를 것을 늘리지 않는다.
2. 처음에는 계획표·시간표 없이, 오늘 도장 하나부터 시작한다.
3. 줄어드는 숫자와 끊김 경고를 보여 주지 않는다. 놓쳐도 쌓인 것은 그대로다.
4. 새 기능은 뒤에서 열린다. 처음에는 보이지 않거나, 고르지 않아도 저절로 적용된다.
5. 근거를 확인하지 못한 것은 가설로 적고, 써 본 사람의 반응으로 확인한다.

자세한 이유와 근거 수준은 `PRD.md`에 있음

- 칸 세 개에 도장만 찍는 아주 단순한 루틴표 시안
- 처음에는 계획표를 짜지 않고 일단 시작하는 것이 목적
- 기능과 그림은 앞으로 바뀔 수 있음

## 쓰는 법

- 오늘 칸을 누르면 진한 도장(다 했어요), 한 번 더 누르면 연한 도장(조금만 했어요), 또 누르면 비움
- 연한 도장도 그날은 한 걸로 침
- 칸은 처음 3개이고, 도장 찍은 날이 3일이면 기록, 28일이면 칸 늘리기(최대 12칸), 60일이면 달력·일정 메모가 열림. 일수의 근거와 한계는 `PRD.md`의 "칸 열림 일정과 근거 수준"에 있음
- 처음 여는 사람에게는 첫 방문 선물로 도장 1일이 미리 쌓여 있음. 메인 화면 맨 위 «로드맵» 띠 머리줄에 "(🎁 첫 방문 선물 1일 포함)"으로 표시함 (처음 3일 동안)
- 배경 색은 «🛍 상점 → 배경 색» 탭에서만 바꿈(설정에는 색 고르는 곳이 없음). 기본·복숭아·바다는 무료이고 가을낙엽·장미·라임·라벤더·햇살은 각 1,000원이며, 단계(28·60일)가 열려도 색은 바뀌지 않음. 도장 일수는 처음 쓰는 사람의 첫 도장 선물 1일을 포함해서 셈
- "내 루틴" 카드에 칸마다 아이콘, 이름, 그 칸을 찍은 누적 일수("12일째")를 보여 줌. 연속이 아니라 누적이고 줄어드는 숫자는 없으며 "자리 잡았다" 같은 판정은 하지 않음. 그 아래에 별도 "성장 단계" 카드를 두어 지금이 1단계(루틴 익히기, 0~59일)인지 2단계(일정표 키우기, 60일 이후)인지, 열리는 기능(3일 기록·28일 칸 늘리기·60일 달력·일정), 남은 일수, 다음 색, 아직 만들지 않은 예고 기능(시간 정하기·반복 일정·알림·일정 색 구분·여러 달력 합쳐 보기, 준비 중 표시, 열리는 일수 없음)을 한곳에 모아 보여 줌
- ⚙ 설정의 "의견 보내기"에서 글을 적고 "제출하기"를 누르면 서버(`POST /api/feedback`, `server/feedback.py`)가 만든 사람의 Gmail로 메일을 보낸다(저장하지 않고 본문을 로그에 남기지 않음, 한도 IP당 분당 3번, 쓴 날수·도장 수가 글 끝에 붙음). 환경변수 `FEEDBACK_SMTP_USER`(보내는 Gmail)·`FEEDBACK_SMTP_PASSWORD`(앱 비밀번호, Secret Manager)·선택 `FEEDBACK_TO`. 설정이 없거나 서버가 없으면(GitHub Pages) 실패 안내가 나오고 "글 복사하기"로 복사해 보냄
- ⚙ 설정에 "도우미 말투"(이름·말투·이모지)와 "내 OpenAI 키(선택)"가 있음. 키는 이 브라우저 탭의 `sessionStorage`에만 두고(탭을 닫으면 지워짐) 요청마다 `X-User-LLM-Key` 헤더로 보내며, 서버는 저장·기록하지 않고 화면에는 끝 네 자리만 보임. 서버를 `BYOK_MODE=required`로 띄우면 키가 없을 때 운영자 키를 쓰지 않고 안내만 함(기본 `optional`은 키가 없으면 운영자 키)
- (서버가 `CREDITS=on`일 때만) 맨 위 줄의 "🛍 상점"에서 일회 구매 상품(배경 색 5가지, 오늘의 좋은 말, 지난 기록 돌아보기 각 1,000원)을 산다. 도우미 대화는 하루 무료 한도 안에서 무료이고, 한도를 다 쓰면 추가 대화권(100번 1,000원 등)을 사서 계속 쓸 수 있다(한도 숫자와 가격은 근거 없는 임시값, 남은 무료 횟수는 화면에 보이지 않음). 결제는 토스페이먼츠 **테스트 환경**이며 실제로 돈이 빠져나가지 않는다. 가격은 임시값이고 배포하지 않았다.
- 칸이 열리는 3·28·60일에 축하 창이 한 번 뜨고 그때 열리는 색을 알려 줌(결제 제안 없음). 누적 60일이 되면(또는 "지난 기록 돌아보기"를 사면) 주간 카드 아래 "달력 · 일정"에서 달 단위 달력을 보고, 60일 이후에는 날짜를 눌러 120자까지 할 일·일정을 적음(브라우저에만 저장).
- 위쪽 «기록» 버튼(무료, 2026-11-04 사용자 요청): 날짜별 메모·일기 한 개를 «하루»·«주간(7일을 한 화면에서)»·«5년(같은 날짜의 최근 5년)» 세 가지로 보고 쓴다. 같은 데이터를 세 방식으로 볼 뿐이라 도장 일수와 관계없이 쓸 수 있고, 이 기기(브라우저)에만 저장된다. «🎀 꾸미기»에서 메모지 종류(상점 «메모지 7종», 임시 1,000원)를 고르고 산 스티커 팩의 스티커를 «하루» 글 칸에 붙여 옮길 수 있다.
- 누적 60일 달력에서 날짜를 누르면 상점에서 산 스티커 팩 7종(동글동글·하루·기념일·생활 필수·카페·오피스·하이라이트 각 1,000원 임시, 이모지·하이라이트는 날짜 숫자에 형광펜·밑줄·동그라미)의 스티커를 하루 최대 3개 붙일 수 있음(상점의 스티커 상품은 일수와 관계없이 항상 보이고, 달력이 열리기 전에는 쓸 수 없다고 안내함).
- 색 테마 바다·장미는 무료. 상점의 디자인 테마 5종(공책·레트로·구름·우주 행성·도넛, 각 1,350원 임시)은 배경 무늬·카드·버튼 모양까지 바뀌며, «미리 보기»로 사기 전에 입어 볼 수 있음.
- 할 일 칸 그림은 물건 하나를 크게 그린 그림으로 바꿨고(기상=알람시계, 원서=ABC 책 등) 물 마시기·공부·일기·잠·청소·양치·영양제·계획·음악을 더함. 상점의 «할 일 아이콘 스타일 팩» 3종(귀여운·심플 선·파스텔 스티커, 각 1,000원 임시)을 사면 ⚙ 설정의 «할 일 아이콘 스타일»에서 25개 그림의 분위기를 바꿀 수 있음.
- «로드맵»(2026-11-06 사용자 요청, 머지 게임처럼 목표를 메인 화면에 둠): 메인 화면 **맨 위**에 가로로 넘겨 보는 띠가 있다. 시작·3일 기록·28일 칸 늘리기·60일 달력·일정이 달성(✔)·다음 목표(남은 일수와 진행 막대)·잠김(🔒)·먼저 열어 둠(🔓)으로 보이고, 아직 만들지 않은 시간 정하기·반복 일정·알림·일정 색 구분·여러 달력 합쳐 보기는 «준비 중»(열리는 날 없음)이다. 띠를 누르면 전체 로드맵 창(1단계 루틴 익히기·2단계 일정표 키우기 설명 포함)이 열린다. 상점 안에는 로드맵이 없고 «기능 바로 열기» 탭에 돈을 내고 먼저 여는 상품만 있다. 근거로 읽은 것: Merge Mansion 공식 지원 글(진행 목표를 보드 상단에 좌우로 넘겨 보이게, 상점은 우상단 버튼). 다른 머지 게임은 화면 배치를 확인하지 못했다.
- 도장 모양 바꾸기는 없앴다(도장은 동그라미 하나). 기존 구매 기록은 DB 에 남지만 화면이 무시함.
- 아이콘과 스티커의 기능 통합(2026-11-06 사용자 결정): 산 스티커·아이콘 그림은 «할 일 칸 바꾸기»에서 칸 그림으로 고를 수 있고(칸에 `art` 로 저장), 아이콘 팩 3종의 글리프 20개는 붙이는 스티커로도 쓴다(스티커 목록에 같은 상품 id 로 들어감). 아이콘 팩의 «쓰기»(기본 칸 그림 전체를 한 스타일로 바꾸기)는 그대로 있다. 상점에서도 «스티커·아이콘» 한 탭에 있다.
- 화풍 더 섞기(2026-11-06 사용자 요청): 스티커 팩 4종 추가 — 낙서(삐뚤빼뚤 선·색 어긋남, 2달러)·말랑 3D(광택·그림자, 3달러)·손글씨 레터링(한글 글자 스티커, 1달러)·마커 표시(동그라미·체크·형광 박스, 1달러). 각 16종, 스티커 팩은 모두 17종.
- 오늘의 한마디 개편(2026-11-06 사용자 요청): 옛 격언·속담 대신 일상에 도움이 되는 응원 문장을 언어별(10개 언어×16개, `server/affirmations.json`)로 뽑는다. 문장은 직접 쓴 짧은 글이며 SNS 문구는 가져오지 않았다. `/api/quote?lang=` 가 지금 언어의 문장을 주고, lang 이 없으면 예전 격언 DB를 쓴다.
- 일정 모음 팩(2026-11-06 사용자 요청): 스티커 팩 하나로 피부관리·네일·미용실·병원·운동 14종·모임·공부·집안일·여행·경조사까지 일상 일정 89종을 표현한다(2달러). 다른 팩도 같은 일정 목록을 자기 화풍으로 늘려 갈 계획(공통 목록 + 팩마다 그리기).
- 스티커 전면 재구현(2026-11-06 사용자 결정): 화풍 설계서 `docs/sticker-style-guide.md`를 먼저 쓰고 팩당 30종을 하나씩 새로 그린다. 그림은 `tools/stickers/`(부품 라이브러리 parts.js, 팩별 packs/*.js, build.js review/apply)로 만들고 192·48·26px 검수 그림판을 본 뒤 앱에 넣는다. 완성: 펜 일러스트(sticker_sched), 색연필(sticker_life 자리).
- 가격(2026-11-06 사용자 결정): 모든 가격은 1달러 기준(1달러≈1,344원을 올림해 1,350원). 꾸미기 상품은 세 가격대로 나눈다 — 1달러(1,350원): 배경 색 5가지·동글동글·하루·기념일·하이라이트 스티커, 2달러(2,700원): 메모지 번들 2·아이콘 팩 3·색연필 일정(옛 생활 필수 자리)·펜 일러스트 일정·오피스 스티커, 3달러(4,050원): 디자인 테마 5가지·카페 스티커. 기능(오늘의 한마디·지난 기록)은 1달러, 먼저 열기는 1·2·3달러와 전체 5달러, 대화권 충전(1,000·5,000·10,000원)은 그대로. 메모지는 노트 4종(줄 노트·모눈·점 격자·그리드)과 감성 4종(크라프트·노란 메모·편지지·새로 만든 수채 하늘) 두 번들이며, 옛 «메모지 7종»을 산 기록은 그 7종을 그대로 쓴다.
- 단계 선물(2026-11-06 사용자 결정): 3일·28일·60일을 지날 때 각각 1달러·2달러·3달러 가격대의 꾸미기 팩 1개를 무작위로 선물한다(오래 지속할수록 더 비싼 팩). 그 가격대를 다 가졌으면 가까운 낮은 가격대, 그다음 높은 가격대에서 뽑는다. 메인 로드맵의 각 단계에 도착 선물 가격대가 적혀 있고, 선물이 오면 «이름 (N원 상당)»으로 알린다. 기능 바로 열기로 산 단계는 선물이 없다.
- 상점의 «기능 바로 열기»(옛 «바로 열기»→«먼저 열기»): 달러 배수 가격(1달러≈1,344원, 2026-11-04 조회 환율을 올림해 1,350원). 기록 1달러(1,350원), 칸 늘리기 2달러(2,700원), 달력·일정 메모 3달러(4,050원), 모든 단계 5달러(6,750원, 개별 합계 6달러보다 쌈). 환율 갱신 기준은 정하지 않았다(임시값).
- 주간 카드 아래 "이번 주 N/7 · 이어 온 날 N일": 이어 온 날은 이틀 연속 빠뜨리면 0부터 다시 세고, 누적 일수·열림·구매는 그대로.
- 처음 열면 맨 위에 소개 카드(왜 단순한지, 써 보고 의견을 달라는 부탁)와 사용법 카드("알겠어요" 카드)가 나옴. 둘 중 하나라도 닫으면 왼쪽 위에 "안내" 버튼이 나타나, 누르면 두 카드를 다시 볼 수 있음 (두 카드가 모두 열려 있을 때는 이 버튼을 숨김)

## 언어

- 한국어, English, 简体中文, 繁體中文, 廣東話, Bahasa Indonesia, Tiếng Việt, Español, Suomi, Svenska
- 화면 오른쪽 위 ⚙ 설정에서 언어를 고를 수 있고, 고른 언어는 기억함. 설정에는 색 테마, 의견 보내기, 개인정보 안내, 내 기록 지우기(두 번 눌러야 지워짐)도 모여 있음
- 처음에는 브라우저 언어를 따라감

## 저장

- 기록은 쓰는 기기의 브라우저에만 저장됨
- 계정이나 로그인 없음
- 브라우저 사이트 데이터를 지우면 기록도 지워짐
- 기록을 코드로 옮기는 기능은 없앴음(2026-10-21: 코딩을 모르는 사람이 많고 주로 휴대폰으로 써서 어렵다는 판단). 그래서 폰을 바꾸거나 브라우저 데이터를 지우면 기록이 사라짐
- 칸을 빼도 이미 찍은 도장은 남아서, 도장 수와 열린 칸이 줄지 않음
- 화면을 열어 둔 채 날짜가 바뀌어도, 다시 보면 오늘 칸이 새 날짜로 바뀜

## 구성

- `index.html` 한 파일. 도장 찍기는 서버 없이 동작한다.
- `server/` 선택 기능 **대화형 도우미**(루틴 코치 친구) 서버. FastAPI, 무상태, `POST /api/chat` 하나(NDJSON 스트리밍). 오른쪽 아래에 떠 있는 💬 버튼을 누르면 채팅창이 떠오르며(폰에서는 아래에서 올라오는 시트, 도장 화면은 그대로 보임), 루틴 만들기가 어렵다는 고민을 들어 주고(듣기), 방법은 근거 카드(`server/cards.json`, 10장, 출처·확인 수준·한계 표기, 사용자 검수 전)에서만 말하며(조언), 오늘의 한 걸음을 퀘스트 카드로 주며(퀘스트, "받기"를 누르면 오늘 화면에 "오늘의 한 걸음" 한 줄로 보였다가 날짜가 지나면 말없이 사라짐), 이 앱에 대한 질문은 서버의 앱 안내로 답한다(앱). 맞는 카드가 없으면 "근거를 못 찾았어요"라고 알리고 듣기로 돌아간다.
  - 대화는 브라우저 `localStorage`에 저장하고, 요청마다 최근 10턴을 보낸다(할 일 목록은 없앴고 `todos`는 항상 빈 배열, 칸 이름·도장 일수·오늘 칸 상태(안 찍음/진하게/연하게, `context.today`)는 도우미가 앱의 일부이므로 허락 절차 없이 늘 `context`로 함께 보내고(2026-10-21 사용자 결정, 개인정보 안내에는 따로 적지 않음. 오늘 상태는 도우미가 "아침 먹기는 아직이네요"처럼 구체적으로 짚으려고 보냄), 어제까지의 도장 날짜별 기록·사진은 보내지 않음). 서버는 대화를 저장하거나 로그에 남기지 않는다. 위기 표현(자해 등)은 화면에서 먼저 걸러 서버로 보내지 않고 안전 안내를 보여 주며 서버도 한 번 더 거른다. 서버가 없거나 실패해도 도장 찍기는 그대로 동작한다.
  - 로컬 실행(키 없이 가짜 응답): `cd server && pip install -r requirements.txt && python -m uvicorn main:app --port 8893` → http://localhost:8893 (화면과 API가 같은 주소). 진짜 LLM은 환경변수 `LLM_PROVIDER`(openai/gemini/claude)·`LLM_API_KEY`·`LLM_MODEL`로 켠다(키는 파일에 적지 않는다).
  - 도장 그림: `POST /api/stamp` `{"name": 루틴 이름(≤20자)}` → `{"svg": "<svg …>"}`(정리된 SVG 한 개, viewBox 0 0 64 64, 16000자 이하). 허용 태그 밖·`on*`·href·바깥 `url()`은 서버에서 지우고, 이름이 위기 표현이면 그리지 않는다(422). 한도는 대화와 따로 IP당 분당 5회·전체 분당 30회. 오류 400 empty / 422 refused / 429 busy / 502 failed. 키 없는 가짜 LLM은 고정 모양 SVG를 준다. 이름·그림은 저장·로그하지 않는다.
  - 도우미 캐릭터: `POST /api/chat` 본문의 선택 필드 `character: {"name": ≤20자, "speech": "casual"|"polite", "emoji": "none"|"some"|"often"}`(브라우저에 저장해 요청마다 보냄, 서버는 저장 안 함). 필드가 없거나 객체가 아니면 지금까지와 글자까지 같은 기본 동작이고, 허용 목록 밖 값은 기본값(polite·some)으로 정리한다. 설정이 바꾸는 것은 말투 줄과 이름 칸뿐이며 안전·범위·근거 카드·위기 규칙은 설정보다 앞에 있어 그대로다(위기·범위 밖·"근거를 못 찾았어요" 안내 문구는 말투와 무관). 평가: `run_eval.py --character '{…}'`.
  - BYOK(사용자 키): `POST /api/chat`·`/api/stamp`는 요청 헤더 `X-User-LLM-Key`(길이 ≤200, 공백 없는 출력 가능한 ASCII)로 받은 사용자 키를 그 요청 동안만 쓰고(요청마다 새 LLM 객체, 캐시 없음) 저장·로그·응답·오류 메시지에 남기지 않는다. 환경변수 `BYOK_MODE`: `optional`(기본, 헤더가 있으면 그 키로 없으면 운영자 키) / `required`(헤더가 없으면 운영자 키를 절대 쓰지 않고 안내만). 오류: 대화는 NDJSON `{"type":"error","key":"keyMissing"|"keyInvalid"|"keyLimit"}` 한 줄 뒤 종료(HTTP 200), 도장 그림은 401 keyMissing·keyInvalid / 429 keyLimit. 제공사 오류 문구는 전달하지 않고 인증 실패→keyInvalid, 한도·결제(429·402·insufficient_quota)→keyLimit으로만 나눈다. 속도 제한은 사용자 키여도 그대로. 사용자 키는 모양으로 제공사를 고른다: `sk-ant-`로 시작하면 Claude, `AIza`로 시작하면 Gemini(OpenAI 호환 주소), 그 밖(`sk-`, `sk-proj-` 등)은 OpenAI, 모델은 각 제공사 기본값(`llm.PROVIDERS`). 고른 제공사는 로그·응답에 남기지 않고, 운영자 키 경로(헤더 없음)는 `LLM_PROVIDER` 그대로다. 오류 분류는 OpenAI·Anthropic·Gemini 모양을 모두 본다(Gemini 호환 주소는 잘못된 키에 401이 아니라 400 + `API_KEY_INVALID`를 주는 경우가 있음, 커뮤니티 보고).
  - 대화 품질(2026-10-21 사용자 실사용 불만 반영): 말하는 내용의 출처를 셋으로 나눈다 — 루틴 방법·효과는 근거 카드만, 이 앱에 대한 사실은 서버가 가진 앱 안내(`policy.APP_GUIDE`)만, 그 밖의 일반 정보는 "널리 알려진 일반 정보이고 출처는 확인하지 못했어요"라고 밝히고 숫자·연구 인용 없이. 모드에 `app`·`general`을 더했고(done 이벤트에 `basis`: cards/app/general/none), 듣기 모드는 질문만 되풀이하지 않게 직전 답이 질문이었으면 이번엔 요약·선택지·다음 한 걸음으로 끝내게 한다. 말투는 설정이 바뀐 직후 옛 말투 도우미 답을 생략하고 마지막 사용자 말 뒤에 말투 한 줄을 붙여 지킨다. 측정 도구: `python evals/probe.py --env <.env 경로> --tone --convo`.
  - '내 할 일' 목록 제거(2026-10-21 사용자 결정): 이 앱은 일정관리 앱이 아니라 루틴 시작을 돕는 앱이라 화면에서 할 일 목록을 없앴다. 서버는 `todos`를 이전 버전 호환으로 계속 받지만(오면 맥락으로만 씀) `organize`(정리) 모드는 없앴고 모델이 골라도 `listen`으로 처리한다. 한 번만 하는 일(병원·약속)이나 일정을 말하면 `app` 모드가 "지금은 적어 두지 않아요, 이 앱은 루틴 시작이 목적이에요"라고 부드럽게 말하고 "오늘 해 볼 한 걸음 하나만 정해 볼까요?"나 반복할 일이면 "칸으로 만들어 매일 찍어 볼까요?"로 잇는다(앱 안내에 '일정관리 앱이 아니라 루틴 시작을 돕는 앱' 추가, 언제 기능이 붙는다는 날짜·약속은 말하지 않음).
  - 시험: 작업 폴더 루트에서 `python -m pytest -q`(2026-11-04 기준 235개, 가짜 LLM·가짜 토스 승인). 크레딧 시험은 `server/tests/test_credits.py`.
  - 크레딧·결제 로컬 실행: `CREDITS=on CREDIT_DB=<파일 경로> LLM_PROVIDER=fake python -m uvicorn main:app --app-dir server --port <포트>`. 토스 테스트 키는 환경변수 `TOSS_SECRET_KEY`·`TOSS_CLIENT_KEY`(`test_`로 시작하는 값만 쓰고 live 키는 무시함). 키 값은 문서·채팅에 적지 않는다. 서버는 로컬 SQLite라 운영용이 아님.
  - (이전 문구) `cd server && python -m pytest tests`(143개였던 시점의 안내, 지금은 위 루트 실행을 쓴다). 평가 세트: `server/evals/`(사례 15건 `cases.json`, 판정 `judge.py`, 실행기 `run_eval.py`). `python evals/run_eval.py --fake --all`은 비용 없이 흐름만 확인하고, `--real --env <.env 경로>`는 진짜 LLM으로 핵심 6건(호출 약 12번)을 돌린다(.env 값은 그 프로세스 안에서만 쓰고 출력하지 않는다). 말투·한계 문장 검사는 휴리스틱이라 사람이 답을 읽어야 한다. 진짜 LLM 호출은 아직 시험하지 않았다. 카드 밖 주장을 프롬프트만으로 완전히 막을 수는 없고 평가 세트도 아직 없다.
